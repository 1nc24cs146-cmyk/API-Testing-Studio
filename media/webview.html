⬇ — downloads on Antigravity

Privacy: everything ApiDiya stores stays on this device only — collections, environments, suites, test runs, mocks and history in local editor storage (never synced to a cloud), and saved auth tokens in your operating system's keychain. No account, no cloud, no telemetry. The only network traffic is the request you send, to the URL you typed.

AI — test generation, on your machine


AI runs locally via Ollama on your own machine — nothing leaves the device. No cloud model, no API key. Ollama must be running with a model pulled (see the setup note below); if it isn't, ApiDiya says so instead of pretending AI ran.























Ollama setup: install Ollama, run ollama pull llama3.1:8b (or set another model above), then start it — ollama serve. Without a running Ollama and a pulled model, the AI buttons report that clearly.



Test suites


Tick requests, name the suite, save it, then run it. A suite run uses each saved request as stored.








Data-driven runs


Run a saved suite once per data row. Paste CSV (first line = column names) or a JSON array of objects. Each row's values replace {{variables}} in the URL, headers, query params and body for that run — row values win over the environment. Rows are used only for the run and are not stored.

AI mock responses: "Generate with AI" on a mock asks your local Ollama for a realistic body matching the endpoint's OpenAPI schema (from an imported spec, or a JSON Schema pasted on the matching saved request). The body is checked against the schema before it is saved — a body that does not fit is reported, never stored. Without a schema, or without Ollama running, it says so instead of guessing.
